# work-rules

**Многослойная система разработки с ИИ-агентами: методология + работающие перехватчики.**

Как сделать так, чтобы качество работы агента не зависело от того, «постарался» ли он в этот раз.

Всё внутри выведено из практики репозитория, где основную часть кода пишут агенты, а один
нетехнический владелец принимает решения. Каждое правило здесь оплачено конкретным инцидентом —
и почти каждое сопровождается объяснением, каким именно.

---

## Главная идея

> **Инструкция агенту — это пожелание. Проверка — это механизм.**

Всё, что записано только словами («всегда делай X», «не забудь про Y»), выполняется, пока агент
не занят, не спешит и не потерял контекст. В момент, когда это важнее всего, правило нарушается
первым.

Отсюда три следствия, на которых стоит вся система:

1. **Правило, нарушение которого уже стоило дорого, переезжает из текста в код.**
2. **Разрешение выдаётся не по обещанию, а по доказательству**, привязанному к конкретной версии
   изменений.
3. **Проверять надо не только код, но и замысел** — ревьюеры ловят гонки и утечки, но не ловят
   «сделали не то и не так».

## Десять слоёв

Каждый следующий ловит то, что пропустил предыдущий.

| # | Слой | Что ловит | Механизм |
|---|---|---|---|
| 0 | Замысел | «сделали не то» | план до кода, согласование с владельцем |
| 1 | Задача | «непонятно, что считается готовым» | задача в трекере, поле «готово, когда» |
| 2 | Изоляция | агенты мешают друг другу и человеку | отдельная рабочая копия на агента |
| 3 | Дисциплина | «сломалось разом, откатывать нечего» | инкрементальные коммиты, батчинг правок |
| 4 | Ограничители | опасные и дорогие команды | перехватчики на уровне инструментов |
| 5 | Ревью | ошибки в коде | ревьюеры + **расписки** |
| 6 | Второе мнение | слепые зоны первой модели | независимый внешний ревьюер |
| 7 | Пайплайн | «у меня локально работало» | CI как единственная истина |
| 8 | Память | потеря контекста между сессиями | разделение «как работаем» / «что делаем» |
| 9 | Мета-слой | защиты тихо сломались | тесты на сами защиты |

## Ядро: расписки

Самая переносимая часть системы — и та, ради которой стоит смотреть код.

Коммит крупного или критического изменения **блокируется**. Обойти можно флагом
`REVIEW_DONE=1` — но сам по себе флаг не значит ничего. Когда ревьюер **синхронно** завершает
работу, отдельный перехватчик записывает файл с отпечатком **того диффа, который ревьюер видел**.
Гейт пересчитывает отпечаток и пропускает, только если у каждого требуемого ревьюера есть свежая
расписка **на эти самые изменения**.

```
     ревьюер отработал                    попытка коммита
            │                                    │
            ▼                                    ▼
   ┌─────────────────┐                  ┌──────────────────┐
   │ расписка:       │   отпечатки      │ пересчитать      │
   │ sha(дифф)       │◄──── равны? ────►│ отпечаток сейчас │
   └─────────────────┘                  └──────────────────┘
            │                                    │
      да ───┴─── коммит проходит          нет ───┴─── «расписка есть,
                                                       но на другой дифф»
```

Что это меняет: проверяемым становится не «ревью недавно было», а «ревьюер видел **этот** код».
Добавили коммит после ревью — расписка перестала подходить, и это правильно.

Детали, каждая из которых оплачена инцидентом (`SYSTEM.md` §7.3): почему отпечаток берётся против
точки ветвления, а не против конца основной ветки; почему фоновый запуск ревьюера не должен
выписывать расписку; почему привязка идёт к рабочей копии сессии; почему ошибка вычисления
отпечатка обязана означать отказ, а не подстановку заглушки.

## Быстрый старт

```bash
git clone https://github.com/Jedesser/work-rules
cp -r work-rules/hooks <ваш-проект>/.claude/hooks
cp work-rules/config.example.json <ваш-проект>/.claude/gates.config.json
# заполнить конфигурацию под проект, зарегистрировать перехватчики
python3 work-rules/ci/check_gates_consistency.py   # проверить обе стороны
```

Подробно — в **[INSTALL.md](INSTALL.md)**. Ставить лучше слоями: каждый полезен сам по себе.

**Требуется:** Python 3.9+ и git. Ни зависимостей, ни сети, ни доступа наружу.

**Совместимость:** скрипты общаются JSON'ом на входе и кодом возврата на выходе, поэтому не знают
ничего про конкретного агента. Примеры регистрации даны для Claude Code; для другого рантайма
меняется только обёртка.

## Если брать только одно

- **Один час** → запрет разрушительных команд (`hooks/guard_bash.py`) плюс правило «каждый агент
  работает в своей копии репозитория». Это ловит самые дорогие и самые тихие потери.
- **Один день** → добавить блокировку коммита крупных и критических изменений с одним ревьюером
  и фиксированным форматом находок.
- **Когда честный флаг перестанет соблюдаться** → расписки. Это происходит раньше, чем кажется.

## Чем это отличается от «просто хорошего CLAUDE.md»

Хороший корневой файл правил тоже нужен — его образец лежит в
[templates/agent-rules.md](templates/agent-rules.md). Но текст правил не может:

- отказать в выполнении команды, которая сотрёт чужую работу;
- отличить «ревью было» от «ревью было на этой версии кода»;
- заметить, что агент правит общую копию репозитория через символическую ссылку;
- посчитать, что один и тот же дифф ревьюят по кругу четвёртый раз;
- сломаться заметно, если сам сломается.

Всё это делает код. Правила остаются короткими — и потому реально соблюдаются.
