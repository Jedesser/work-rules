# Установка

Требуется: Python 3.9+, git. Больше ничего — ни зависимостей, ни сети.

## Быстрый путь (10 минут)

```bash
# 1. Скопировать перехватчики в проект
git clone https://github.com/Jedesser/work-rules /tmp/work-rules
mkdir -p <ваш-проект>/.claude/hooks
# точка в конце пути-источника обязательна: без неё, если каталог уже есть,
# получится .claude/hooks/hooks — и ни один перехватчик не найдётся
cp -r /tmp/work-rules/hooks/. <ваш-проект>/.claude/hooks/
chmod +x <ваш-проект>/.claude/hooks/*.py

# 2. Настроить под проект
cp /tmp/work-rules/config.example.json <ваш-проект>/.claude/gates.config.json
# отредактировать: shared_checkout, critical_paths, red_zone_paths, reviewers

# 3. Зарегистрировать перехватчики
# содержимое settings.example.json влить в <ваш-проект>/.claude/settings.json

# 4. Проверить, что всё живо
mkdir -p <ваш-проект>/ci
cp -r /tmp/work-rules/ci/. <ваш-проект>/ci/
python3 <ваш-проект>/ci/check_gates_consistency.py
```

Каталог `hooks/lib/` копируется вместе с остальным и обязателен: в нём общее ядро,
без которого ни один перехватчик не запустится.

Последний шаг обязателен и должен стать шагом вашего пайплайна: перехватчики ломаются молча,
и без теста поломка выглядит как «всё зелено».

## Что заполнить в `gates.config.json`

| Ключ | Что это | Как выбрать |
|---|---|---|
| `base_ref` | ветка, относительно которой считается «что я изменил» | обычно `origin/main` или `origin/master` |
| `shared_checkout` | абсолютный путь к общей копии, куда агентам писать нельзя | путь, открытый у вас в IDE; `null` — выключить |
| `critical_paths` | пути, чья правка требует ревью независимо от размера | пайплайн, инфраструктура, миграции, точки входа |
| `red_zone_paths` | где цена ошибки максимальна | доступ, деньги, права, начисления, подписи |
| `reviewers` | кто обязан отревьюить и когда | начните с одного `always`-ревьюера |
| `require_timeout_for` | команды тестов, требующие внешнего потолка | ваши команды прогона тестов |
| `forbidden_local_commands` | что нельзя запускать локально | тяжёлые production-сборки |

**Списки путей проверяйте по реальному дереву репозитория**, а не пишите по памяти:

```bash
git ls-files | grep -E '<ваш-паттерн>' | head
```

Список, написанный по догадке об именах каталогов, однажды не совпал ни с чем — и критичный код
месяцами шёл мимо положенного ревью, при том что защита выглядела работающей. Предпочитайте
семейства по префиксу (`auth[a-z]*/`) точным перечислениям: перехватить лишнее дешевле, чем
пропустить нужное.

## Ревьюеры

Файлы из `agents/` кладутся туда, где ваш агентский рантайм ищет описания субагентов
(в Claude Code — `.claude/agents/`). Имя в поле `name` должно совпадать с именем в
`reviewers` из `gates.config.json` — по нему выписывается и ищется расписка.

Если ваш рантайм не поддерживает субагентов, роль ревьюера может играть отдельный вызов модели
или второй человек: механика расписок к этому безразлична, ей важно лишь то, что кто-то
подтверждённо посмотрел именно этот дифф.

## Порядок включения

Не включайте всё сразу — систему проще внедрять слоями, и каждый слой полезен сам по себе.

1. `guard_bash.py` — запрет разрушительного. Работает сразу, настройки почти не требует.
2. `worktree_guard.py` — изоляция рабочих копий. Заполните `shared_checkout`.
3. `guard_resources.py` — ресурсные ограничители. Заполните под свои команды.
4. `commit_gate.py` + `subagent_receipt.py` + `preflight_review_guard.py` — ревью с расписками.
   Это ядро; включайте, когда «честный флаг» перестанет соблюдаться.
5. `merge_gate.py` — то же на границе попадания в основную ветку.
6. `issue_link_gate.py`, `plan_gate.py` — учёт и замысел. Последними: они меняют не безопасность,
   а привычки, и их проще принять, когда остальное уже приносит пользу.

## Проверка, что работает

```bash
# должно быть заблокировано
echo '{"tool_name":"Bash","tool_input":{"command":"git rebase main"}}' \
  | python3 .claude/hooks/guard_bash.py; echo "код возврата: $?"   # ждём 2

# должно пройти
echo '{"tool_name":"Bash","tool_input":{"command":"git merge origin/main"}}' \
  | python3 .claude/hooks/guard_bash.py; echo "код возврата: $?"   # ждём 0
```

Проверяйте **обе** стороны. Перехватчик, который блокирует всё подряд, выключат в первый же день,
и это такой же отказ, как и перехватчик, который не блокирует ничего.

## Другой агентский рантайм

Скрипты не знают ничего про конкретного агента. Их контракт:

- **вход** — JSON на стандартном вводе: `tool_name`, `tool_input`, `cwd`, `tool_response`;
- **выход** — код возврата `0` (разрешить) или `2` (запретить, текст в stderr читает агент);
  строка `{"systemMessage": "..."}` в stdout — совет человеку, ничего не блокирующий.

Для другого рантайма меняется только обёртка регистрации, сами скрипты — нет.
